/02  Platform

Three things, done properly

Not another wall
of dashboards.

/ 01

Correlated signal,
one timeline

Metrics, logs and traces land on a single time axis with the deploy markers already drawn in. When p99 doubles at 14:07, the commit that shipped at 14:06 is sitting right there — no tab-switching, no manual timestamp math.

/ 02

Alerts that
earn the page

Thresholds learn your traffic shape, so Tuesday 3am quiet doesn't read as an outage and Black Friday load doesn't read as normal. Related firing alerts collapse into one incident with a ranked probable cause.

/ 03

Cost you can
actually predict

Per-host pricing with cardinality included — no surprise bill because someone tagged a metric with a request ID. Live spend projection sits in the same panel as your ingest volume.

/03  How it works

Install to first insight — one afternoon

STEP 01

Drop in the agent

One binary, one config line. Debian, Alpine, a Kubernetes DaemonSet or bare EC2 — same install path.

$ curl -sSL nordveil.sh | sh
STEP 02

It maps itself

Nordveil walks your service graph, finds the dependencies, and proposes the SLOs it thinks matter.

42 services · 7 SLOs proposed
STEP 03

Tune the noise floor

Two weeks of baseline, then approve or reject each proposed alert. Nothing pages until you say so.

baseline 14d · ready
STEP 04

Go on call calmly

Routing to PagerDuty, Slack or Opsgenie, with the runbook and the last deploy attached to every page.

route → #oncall-platform
